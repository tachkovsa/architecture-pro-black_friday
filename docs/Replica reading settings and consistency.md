# Настройка чтения с реплик и консистентность

## Таблица распределения операций чтения

| **Коллекция** | **Операция чтения**                | **Источник (Primary/Secondary)** | **Допустимая задержка** | **Обоснование**                                                                 |
|---------------|-------------------------------------|-----------------------------------|--------------------------|---------------------------------------------------------------------------------|
| products | Поиск товаров по категории         | Secondary                         | ≤ 5 минут               | Не требует актуальных данных. Риск устаревания минимален |
| products | Проверка наличия товара на складе  | Primary                           | 0                        | Критично для предотвращения продажи недоступного товара                      |
| orders    | Просмотр истории заказов           | Secondary                         | ≤ 10 минут              | Исторические данные редко меняются                                            |
| orders | Проверка текущего статуса заказа   | Primary                           | 0                        | Требует актуального статуса             |
| carts     | Отображение содержимого корзины    | Primary                           | 0                        | Частые обновления                              |
| carts | Аналитика по брошенным корзинам    | Secondary                         | ≤ 1 часа                | Данные для аналитики не требуют мгновенной консистентности                    |

## Расширенное обоснование

### Допустимая задержка репликации

- **products: ≤ 5 минут:** для отображения описаний товаров и категорий допустима небольшая задержка.
- **orders: ≤ 10 минут:** история заказов обновляется редко, но статусы должны быть актуальными. 
- **carts: ≤ 1 час:** аналитика брошенных корзин не влияет на текущие операции.

### Требования к консистентности
- **Primary для критичных операций:**  
  - Проверка наличия товара (`products`) и статуса заказа (`orders`) требуют строгой консистентности. Использование `readConcern: "majority"` гарантирует, что клиент видит последние подтверждённые данные.  
  - Корзины (`carts`) используют `primary`, так как сессия пользователя может изменять данные в реальном времени.

- **Secondary для не критичных операций:**  
  - Аналитика и поиск по категориям допускают `readPreference: "nearest"` для снижения нагрузки на primary.

### Частота обновлений
- **Высокая частота:**  
  - `carts` и `orders` обновляются часто (каждые несколько секунд), поэтому чтение с primary обязательно.  
- **Низкая частота:**  
  - Описания товаров (`products`) меняются редко (раз в день), что позволяет использовать secondary.

### Бизнес-логика
- **Риск продажи недоступного товара:** Если пользователь видит устаревшие данные о наличии, это может привести к отмене заказа.
**Решение:** `readPreference: "primary"` + `maxStalenessSeconds: 0`.  
- **Устаревший статус заказа:** Показ статуса "в обработке" вместо "доставлен" вызовет недовольство клиентов.
**Решение:** `readConcern: "linearizable"`.  

## Примеры команд для MongoDB

```MongoDB
db.products.find({ in_stock: { $gt: 0 } }).readPref("primary");

db.orders.find({ user_id: "..." }).readPref("secondary").maxStalenessSeconds(600);

db.carts.aggregate([...]).readPref("secondaryPreferred").maxStalenessSeconds(3600);
```
