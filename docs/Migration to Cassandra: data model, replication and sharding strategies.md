### **Критичные данные**
| **Сущность** | **Целостность** | **Скорость** | **Подходит для Cassandra?** | **Обоснование** |
|------------------------|------------------|--------------|------------------------------|-----------------|

## Задание 10.2

### Товары (products)

Пример создания таблицы (CQL):
```sql
CREATE TABLE products (
 category TEXT,
 product_id UUID,
 name TEXT,
 price DECIMAL,
 in_stock INT,
 PRIMARY KEY ((category, product_id), price)
) WITH CLUSTERING ORDER BY (price DESC);
```

**Partition Key:** `category`, `product_id`
Равномерное распределение за счёт комбинации категории и UUID.

**Кластерный ключ:** `price`
Оптимизация для частых запросов с фильтрацией по цене.

**Защита от горячих партиций:**
Использование `product_id` (UUID) исключает перекос нагрузки на одну категорию.

### Заказы (orders)

Пример создания таблицы (CQL):
```sql
CREATE TABLE orders (
 user_id UUID,
 order_id TIMEUUID,
 status TEXT,
 items MAP<UUID, INT>,
 PRIMARY KEY ((user_id, order_id), status)
) WITH compaction = { 'class' : 'TimeWindowCompactionStrategy' };
```

**Partition Key:** `user_id`, `order_id`
Группировка заказов пользователя в одной партиции.

**Кластерный ключ:** `status`
Эффективные запросы по текущему статусу.

**Минимизация решардинга:**
`TimeWindowCompactionStrategy` изолирует "горячие" новые заказы от архивных данных.

### Пользовательские сессиии (sessions)

Пример создания таблицы (CQL):
```sql
CREATE TABLE sessions (
 session_id UUID,
 user_id UUID,
 expires_at TIMESTAMP,
 data TEXT,
 PRIMARY KEY (session_id)
) WITH default_time_to_live = 3600;
```

**Partition Key:** `session_id`
Равномерное распределение через хэширование UUID.

**TTL:**
Автоматическое удаление устаревших сессий.

## Задание 10.3

### Стратегии и их применение

| Сущность             | Стратегия                      | Уровень согласованности   | Обоснование                                                                 |
|----------------------|--------------------------------|---------------------------|------------------------------------------------------------------------------|
| Товары               | Read Repair                    | QUORUM                    | Частые чтения позволяют быстро обнаруживать расхождения                    |
| Заказы               | Hinted Handoff + QUORUM        | LOCAL_QUORUM            | Гарантия записи даже при временной недоступности узлов                     |
| История заказов      | Anti-Entropy (Merkle)          | ONE                     | Данные append-only: редко требуют срочного восстановления                  |
| Сессии               | Hinted Handoff                 | ANY                     | Доступность важнее консистентности: сессии можно пересоздать               |

### Компромиссы

**Read Repair:** Увеличивает latency на 10-15%, но обеспечивает сильную согласованность для товаров.

**Hinted Handoff:** Риск потери данных при длительном простое узла, но критично для оформления заказов.

**Anti-Entropy:** Ресурсоёмкая фоновая проверка, подходит для нефункциональных данных.
